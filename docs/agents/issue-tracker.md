# Issue tracker: GitHub

Specs and tickets live in razzeee/flatpak-rs GitHub Issues.
Use the gh CLI.

Read ticket bodies and comments before working on them.
Publish specs as issues and implementation tickets as their sub-issues.
Use native blocking dependencies; if unavailable, record
“Blocked by: #…” in the ticket body.
Use GitHub issue database IDs when API operations require them.

Apply the labels defined in triage-labels.md.
Work tickets whose blockers are complete.

PRs as a request surface: no.
